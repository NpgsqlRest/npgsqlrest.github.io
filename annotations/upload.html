UPLOAD ​

Mark endpoint as a file upload handler.

Keywords ​

@upload, upload

Syntax ​

code
@upload
@upload for <handler_type> [, <handler_type> ...]
@upload <parameter> as metadata
1
2
3

If no handler is specified (only upload annotation without for), then the default handler will be used. The default handler is large_object unless configured otherwise via DefaultUploadHandler setting. Handler names are matched in any case. @upload <parameter> as metadata turns the upload on and names the parameter that receives the upload metadata, the same as @param <parameter> is upload metadata.

Handler Types ​

There are 4 handler types available:

HandlerKeyDescription
Large Objectlarge_objectStores files using PostgreSQL Large Objects API (default)
File Systemfile_systemStores files on the server file system
CSVcsvParses CSV files and processes rows via PostgreSQL command
ExcelexcelParses Excel files and processes rows via PostgreSQL command

Shared Annotation Options ​

These options are read for every handler:

OptionTypeDefaultDescription
stop_after_first_successboolfalseStop upload after first successful upload when multiple handlers are used. Subsequent files will have status Ignored.
included_mime_typesstringnoneComma-separated MIME type patterns (* and ? are wildcards); a file must match one of them. Without it, every type is accepted.
excluded_mime_typesstringnoneComma-separated MIME type patterns; a file that matches one is rejected.
buffer_sizeint8192Buffer size in bytes for raw content uploads (large_object and file_system).
fallback_handlerstringnoneOnly csv and excel use it: the handler that takes over when they cannot process the file (e.g., large_object, file_system). csv hands over whenever the file was not processed (its format check failed, or its MIME type was not accepted); excel when the workbook cannot be read. The fallback's result is then the result of the upload.

These checks are read by some handlers only:

OptionTypeDefaultHandlersDescription
check_textboolfalselarge_object, file_systemAccept only text files (reject binary content).
check_imagebool/stringfalselarge_object, file_systemAccept only images: true for any supported type, or a comma-separated list of jpg, jpeg, png, gif, bmp, tiff, webp.
check_formatbooltruecsvCheck that the file is text with at least one line break before it is processed.
test_buffer_sizeint4096large_object, file_system, csvHow many bytes of the file the text check reads.
non_printable_thresholdint5large_object, file_system, csvHow many non-printable bytes the text check tolerates before the file counts as binary.

Every option can be prefixed with its handler's name (csv_delimiters, excel_sheet_name, file_system_path), which is how two handlers on one endpoint get different values. When both the plain and the prefixed key are present, the plain key wins. Keys are matched in any case (since 4.0.0).

Upload Metadata ​

All handlers return upload metadata as JSON with the following common properties:

PropertyTypeDescription

fileNamestringOriginal uploaded file name
contentTypestringMIME type of the uploaded file
sizeintFile size in bytes
successboolWhether the upload succeeded
statusstringStatus message (e.g., Ok, InvalidMimeType)

Handler-specific properties:

HandlerPropertyTypeDescription

file_systemfilePathstringPath where file was saved

CSV Handler ​

Parses CSV files and processes each row via a PostgreSQL command.

Row Command Function Signature ​

The row command function receives up to 4 parameters:

sql
sql
create function my_csv_row_processor(
    _index int,           -- $1: Row index (1-based)
    _row text[],          -- $2: Parsed row values as text array
    _prev_result any,     -- $3: Result of previous row command (for chaining)
    _meta json            -- $4: Row metadata JSON
)
returns any               -- Return value passed to next row as $3
1
2
3
4
5
6
7

Row Command Parameters ​

ParameterTypeDescription
$1intRow index (1-based, includes header row)
$2text[]Parsed row values as text array (e.g., _row[1], _row[2], etc.)
$3anyResult of previous row command execution (see below)
$4jsonRow metadata JSON object

Row chaining with $3: The return value from each row command is passed to the next row as $3. For the first row, $3 is NULL. If the row command returns void (no return value), $3 will be NULL for the next row. This enables accumulating values across rows (e.g., counting rows, summing values).

Row Metadata Structure ($4) ​

The metadata JSON passed to each row command contains:

json
json

    "user_id": "1",
    "user_name": "alice",
    "name_identifier": "1"
  }
}

Multiple File Uploads ​

Upload endpoints support multiple files in a single request. The metadata will be returned as a JSON array with one entry per file.

Behavior ​

  • Enables multipart/form-data file uploads
  • Handlers process the uploaded file (storage, validation, parsing)
  • Metadata parameter receives file information (name, size, type)
  • All uploads are transactional - errors trigger rollback
  • See Upload Options for configuration
